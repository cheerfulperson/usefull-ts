## 1\. Разница между синхронными и асинхронными функциями

Синхронные функции выполняются последовательно, блокируя выполнение кода до завершения текущей операции. Асинхронные функции запускают операции, а результат обработки возвращается позже, не останавливая основной поток выполнения.

| Параметр | Синхронные функции | Асинхронные функции |
| --- | --- | --- |
| Выполнение | Блокирующее | Неблокирующее |
| Возврат значения | Немедленный результат или исключение | Обычно возвращают `Promise` (отложенный результат) |
| Обработка долгих операций | Блокирует UI или основной поток | Выполняется параллельно, не мешает основному потоку |
| Обработка ошибок | Через `try/catch` | Через `.catch()` или `async/await/try…catch` |

```js
// Синхронная функция
function syncAdd(a, b) {
  return a + b;
}
console.log(syncAdd(2, 3)); // 5

// Асинхронная функция
async function asyncAdd(a, b) {
  return a + b;
}
asyncAdd(2, 3).then(console.log); // 5 (не блокирует выполнение)
```

## 2\. Что такое AJAX?

AJAX (Asynchronous JavaScript and XML) — подход для выполнения HTTP-запросов из браузера без перезагрузки страницы. Несмотря на название, данные часто передаются в формате JSON, а не XML.

*   Основные API:
    
    *   `XMLHttpRequest` (старый способ)
        
    *   `fetch` (современный способ, возвращает `Promise`)
        
*   Применяется для динамического обновления контента и взаимодействия с сервером без перезагрузки.
    

## 3\. Что такое same-origin policy в контексте JavaScript?

Same-Origin Policy — браузерное ограничение, по которому скрипты могут взаимодействовать только с ресурсами того же происхождения. Происхождение определяется как комбинация:

*   Протокол (`http`/`https`)
    
*   Домен (хост)
    
*   Порт
    

Запрещается чтение данных с другого происхождения, если сервер явно не разрешил это через CORS.

## 4\. Что такое цикл событий (event loop) и как он работает?

Event Loop — механизм, который управляет выполнением кода, сбором и обработкой событий, а также выполнение подзадач и отложенных вызовов.

1.  **Call Stack** хранит вызываемые функции.
    
2.  Когда стек пуст, движок проверяет **Microtask Queue** (промисы, `queueMicrotask`).
    
3.  После обработки всех microtasks движок переходит к **Macrotask Queue** (таймеры, события ввода/вывода, `setTimeout`, `setInterval`).
    
4.  Цикл повторяется, обеспечивая неблокирующее выполнение.
    
```text
┌───────────────┐     ┌─────────────────┐
│   Call Stack  │ →   │    Выполнить    │
└───────────────┘     └─────────────────┘
        ↓                      │
 When empty                    ↓
        ↓             ┌─────────────────┐
┌───────────────┐     │  Microtasks     │
│ Macrotask Q   │ ←── │ (Promises...)   │
└───────────────┘     └─────────────────┘
```

## 5\. Разница между микро- и макрозадачами в event loop

*   **Macrotasks (макрозадачи)**
    
    *   setTimeout, setInterval
        
    *   I/O события (клики, сетевые запросы)
        
    *   UI-рендеринг
        
*   **Microtasks (микрозадачи)**
    
    *   Promise callbacks (`.then`, `.catch`, `.finally`)
        
    *   `queueMicrotask`
        
    *   MutationObserver
        

Порядок выполнения:

1.  Выполняется одна макрозадача.
    
2.  Затем обрабатываются все микрозадачи до их исчерпания.
    
3.  Браузер может перерисовать UI.
    
4.  Переход к следующей макрозадаче.
    

## 6\. Расскажите о queueMicrotask

`queueMicrotask` — API для добавления функции в очередь микрозадач. Выполняется сразу после текущей макрозадачи и перед следующей макрозадачей.

```js
console.log('start');

queueMicrotask(() => {
  console.log('microtask');
});

setTimeout(() => {
  console.log('timeout');
}, 0);

console.log('end');
// Вывод: start → end → microtask → timeout
```

## 7\. Как работает setTimeout с нулевым таймером (0 ms)?

`setTimeout(fn, 0)` не выполняет функцию мгновенно, а помещает задачу в очередь макрозадач с минимальной задержкой (обычно 4 ms в современных браузерах). Код в стеке выполняется досрочно, затем микрозадачи, и только потом макрозадачи, включая этот „нулевой“ таймер.

## 8\. Что такое промисы (Promises)?

Promise — объект, представляющий конечный результат асинхронной операции. Состояния:

*   **pending** — ожидание
    
*   **fulfilled** — успешно выполнен (`resolve`)
    
*   **rejected** — отклонён с ошибкой (`reject`)
    

Методы:

*   `.then(onFulfilled, onRejected)`
    
*   `.catch(onRejected)`
    
*   `.finally(onFinally)`
    
```js
const promise = new Promise((resolve, reject) => {
  // асинхронная операция
  setTimeout(() => resolve('result'), 1000);
});

promise
  .then(value => console.log(value))
  .catch(err => console.error(err))
  .finally(() => console.log('done'));
```

## 9\. Плюсы и минусы использования Ajax

| Плюсы | Минусы |
| --- | --- |
| Динамическое обновление контента без перезагрузки | Сложнее отлаживать по сравнению с простыми переходами |
| Меньше сетевой нагрузки (запрашиваются только данные) | Необходимость обработки различных ошибок сетевого уровня |
| Улучшенный UX благодаря плавным интерфейсам | Требует поддержки CORS и правильной настройки серверов |
| Широкая поддержка в браузерах | Потенциальные проблемы с историей браузера (back/forward) |

## 10\. Подходы при работе с асинхронным кодом

*   **Колбэки** — простой, но подвержен «адской пирамиде колбэков»
    
*   **Промисы** — улучшают читаемость и позволяют цепочки `.then`
    
*   **async/await** — синтаксический сахар над промисами, более похож на синхронный код
    
*   **Генераторы** + `co`\-библиотеки — раннее решение до появления `async/await`
    
*   **RxJS/Observables** — для сложных потоков данных и событий, позволяет отменять и комбинировать потоки
    

## 11\. Преимущества использования промисов вместо колбэков

*   **Читаемость**: линейные цепочки `.then` вместо вложенных функций
    
*   **Управление ошибками**: единый `.catch` для всей цепочки
    
*   **Композиция**: методы `Promise.all`, `race`, `any`, `allSettled`
    
*   **Предсказуемый порядок**: микрозадачи выполняются сразу после текущего стека
    
*   **Возврат значений**: каждый `.then` возвращает новый промис, упрощая передачу данных дальше
    
## 12\. Что такое callback-функция? Что такое Callback Hell?

Callback-функция — это функция, переданная в другую функцию как аргумент, которая будет вызвана после завершения некоторой операции. Обычно она используется для продолжения выполнения кода после асинхронного действия (например, чтения файла, HTTP-запроса, таймера).

Callback Hell (или Pyramid of Doom) возникает, когда несколько колбэков вложены друг в друга, создавая трудно читаемую и поддерживаемую «пирамиду»:

```js
doStep1(arg1, (err, result1) => {
  if (err) throw err;
  doStep2(result1, (err, result2) => {
    if (err) throw err;
    doStep3(result2, (err, result3) => {
      if (err) throw err;
      // и так далее...
    });
  });
});
```

## 13\. Проблемы при использовании callback-функций

*   **Читаемость**: глубокие вложенности усложняют понимание потока выполнения.
    
*   **Обработка ошибок**: дублирование `try/catch` или `if (err)` на каждом уровне.
    
*   **Отсутствие композиции**: сложно объединять параллельные операции или дождаться всех колбэков.
    
*   **Утечка контекста**: `this` внутри колбэков может неожиданно ссылаться на другой объект.
    
*   **Отмена операций**: нет встроенного механизма для отмены вложенных колбэков.
    

## 14\. Что такое async/await?

`async/await` — синтаксический сахар поверх промисов, позволяющий писать асинхронный код в стиле синхронного:

*   Ключевое слово `async` перед функцией заставляет её возвращать промис.
    
*   Ключевое слово `await` внутри `async`\-функции приостанавливает её выполнение до выполнения промиса.
    
*   Ошибки ловятся обычным `try…catch`.
    
```js
async function getData() {
  try {
    const response = await fetch('/api/data');
    const json = await response.json();
    return json;
  } catch (err) {
    console.error('Ошибка:', err);
  }
}
```

## 15\. Разница между Promise.all(), Promise.any() и Promise.race()

| Метод | Описание |
| --- | --- |
| `Promise.all()` | Ждёт выполнения всех промисов. Возвращает массив результатов или сразу отклоняется при первой ошибке. |
| `Promise.any()` | Ждёт первого успешно выполненного промиса. Если все промисы отклоняются, возвращает AggregateError. |
| `Promise.race()` | Возвращает результат или ошибку первого завершившегося промиса, остальные игнорируются. |

```js
const p1 = Promise.resolve(1);
const p2 = new Promise(r => setTimeout(() => r(2), 100));
Promise.all([p1, p2]).then(console.log);     // [1, 2]
Promise.race([p1, p2]).then(console.log);    // 1
Promise.any([Promise.reject(), p2]).then(console.log); // 2
```

## 16\. Расскажите про статический метод Promise.allSettled()

`Promise.allSettled()` принимает массив промисов и возвращает промис, который выполняется, когда все входные промисы завершены (независимо от результата). В отличие от `all`, он никогда не отклоняется. Результат — массив объектов с полями `status` и `value` или `reason`:

```js
Promise.allSettled([Promise.resolve(1), Promise.reject('err')])
  .then(results => {
    // [{ status: 'fulfilled', value: 1 }, { status: 'rejected', reason: 'err' }]
  });
```

## 17\. Плюсы и минусы асинхронного программирования в JavaScript

Плюсы:

*   Не блокирует основной поток и UI.
    
*   Позволяет эффективно выполнять операции ввода-вывода.
    
*   Улучшает отзывчивость приложений.
    

Минусы:

*   Сложнее отлаживать, чем синхронный код.
    
*   Риск состязаний (race conditions) и «погрязания» в колбэках.
    
*   Возможность неправильного управления состоянием и утечек памяти.
    

## 18\. Как выполнить несколько асинхронных операций последовательно?

Используя `async/await` внутри цикла или последовательных `await`:

```js
async function runSequential(tasks) {
  const results = [];
  for (const task of tasks) {
    const result = await task(); // ждём завершения перед переходом к следующему
    results.push(result);
  }
  return results;
}

// Пример
const tasks = [
  () => fetch('/api/1').then(r => r.json()),
  () => fetch('/api/2').then(r => r.json())
];
runSequential(tasks).then(console.log);
```

Можно также цепочкой `then`:

```js
task1()
  .then(result1 => task2(result1))
  .then(result2 => task3(result2))
  .catch(err => console.error(err));
```

## 19\. Какие проблемы может вызвать неправильное использование асинхронности в JavaScript?

*   **Race conditions**: неожиданный порядок выполнения операций.
    
*   **Deadlocks**: блокировка, когда промисы зависят друг от друга и ни один не завершается.
    
*   **Утечки памяти**: незакрытые таймеры или незавершённые промисы удерживают ссылки.
    
*   **Накопление задач в очередях**: слишком много незавершённых микрозадач или макрозадач замедлит приложение.
    
*   **Неправильная обработка ошибок**: пропущенные `.catch` или необработанные исключения приводят к «тихим» сбоям.
    

## 20\. Что такое fetch()? Как работает функция fetch()?

`fetch()` — современный Web API для выполнения HTTP-запросов. Возвращает промис, который разрешается объектом `Response`, содержащим статус и тело ответа.

Основные этапы:

1.  Вызов `fetch(url, options)` запускает запрос.
    
2.  Возвращается промис в состоянии `pending`.
    
3.  После получения заголовков и тела промис переходит в `fulfilled`.
    
4.  Телo нужно прочитать методами `response.text()`, `response.json()` и т.п., которые тоже возвращают промисы.

```js
fetch('/api/data', { method: 'POST', body: JSON.stringify({x:1}) })
  .then(response => {
    if (!response.ok) throw new Error(response.statusText);
    return response.json();
  })
  .then(data => console.log(data))
  .catch(err => console.error(err));
```

## 21\. Что такое JSON в JavaScript? Как его можно использовать?

JSON (JavaScript Object Notation) — текстовый формат для обмена данными. Представляет собой объекты и массивы в виде строк.

*   `JSON.stringify(obj)` — конвертирует объект в строку JSON.
    
*   `JSON.parse(str)` — разбирает строку JSON в объект JavaScript.
    

Используется для передачи данных между клиентом и сервером, хранения настроек, обмена данными в локальных файлах.

## 22\. Что такое коэффициент сжатия (compression ratio) в контексте веб-разработки?

Коэффициент сжатия показывает, насколько уменьшился размер ресурса после применения алгоритма сжатия (gzip, Brotli и др.).

```bash
compression ratio = compressed_size / original_size
```

Чем меньше значение, тем эффективнее сжатие. Высокий коэффициент сжатия сокращает время загрузки и экономит трафик пользователя.
