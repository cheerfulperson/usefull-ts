# Ответы по вопросам доступности веб-контента

## 1\. Что такое WCAG?

WCAG (Web Content Accessibility Guidelines) — набор рекомендаций от W3C, призванный сделать веб-контент доступным для людей с различными ограничениями: нарушения зрения, слуха, моторики и когнитивных функций.

Рекомендации сгруппированы по принципам, уровням соответствия и множеству критериев успеха, которые охватывают все аспекты разработки и дизайна.

## 2\. Основные принципы доступности

WCAG опирается на четыре ключевых принципа (POUR):

*   Perceivable (Воспринимаемость): информация и интерфейс должны быть воспринимаемы всеми органами чувств.
    
*   Operable (Управляемость): элементы управления и навигация должны быть доступны через разные способы ввода (клавиатура, голос и т.д.).
    
*   Understandable (Понятность): текст и интерфейс должны быть понятны и предсказуемы.
    
*   Robust (Надёжность): контент должен корректно интерпретироваться разнообразными агентами — браузерами, вспомогательными технологиями и будущими пользовательскими агентами.
    

## 3\. Что такое скринридер?

Скринридер — это вспомогательная технология, которая извлекает из документа структуру и текст, а затем синтезирует речь или выводит на брайлевский дисплей.

Примеры популярных скринридеров: NVDA и JAWS (Windows), VoiceOver (macOS и iOS), TalkBack (Android).

## 4\. Уровни доступности

WCAG делит критерии успеха на три уровня:

| Уровень | Описание |
| --- | --- |
| A   | Базовый набор требований — минимальный. |
| AA  | Средний уровень — рекомендуем стандарт. |
| AAA | Максимальный уровень — расширенные цели. |

Уровень AA обычно является целевым для государственных и коммерческих сайтов.

## 5\. Как скрыть содержимое тега от скринридеров?

Чтобы элемент не озвучивался скринридером, используют:

*   `aria-hidden="true"` — полностью прячет элемент от вспомогательных технологий.
    
*   роль `presentation` или `none` (`role="presentation"`/`role="none"`) — сбрасывает семантику элемента, делая его «пустым».
    

## 6\. Как удалить семантику у элемента?

Для удаления семантического значения у элемента применяют:

*   `role="presentation"` или `role="none"`.
    
*   при необходимости добавить `aria-hidden="true"` для полной невидимости элемента для скринридера.
    

## 7\. Что такое ARIA-роли в веб-приложении?

ARIA (Accessible Rich Internet Applications) — спецификация W3C, позволяющая задать дополнительную семантику для динамического и интерактивного контента.

Роли (`role`) обозначают тип компонента (кнопка, диалог, вкладка, дерево и др.), чтобы вспомогательные технологии корректно его распознали и представили пользователю.

## 8\. Для чего используется атрибут `aria-roledescription`?

`aria-roledescription` позволяет задать альтернативное, более понятное описание роли элемента для пользователя.

Например, вместо стандартного «listbox» можно указать «каталог категорий», чтобы скринридер объявил понятный текст.

## 9\. Какие HTML-атрибуты можно использовать для улучшения доступности?

*   `alt` — описание изображений.
    
*   `<label for>` — привязка текста к полю формы.
    
*   `title` — поясняющая подсказка (использовать экономно).
    
*   `aria-label` и `aria-labelledby` — задают доступное имя элементу.
    
*   `aria-describedby` — указывает на связанный поясняющий текст.
    
*   `tabindex` — управление последовательностью фокуса.
    
*   `lang` — указание языка содержимого.
    

## 10\. Средства и методы тестирования доступности

Автоматизированные инструменты:

*   Lighthouse (в Chrome DevTools).
    
*   axe DevTools.
    
*   WAVE (Web Accessibility Evaluation Tool).
    

Ручное тестирование:

*   Навигация только клавиатурой (Tab, Shift+Tab, Enter, стрелки).
    
*   Проверка с основными скринридерами (NVDA, VoiceOver, JAWS).
    
*   Анализ цветных контрастов с Contrast Checker.
    

Пользовательское тестирование:

*   Сессии с людьми, использующими различные вспомогательные технологии.
    

## 11\. Стандарты доступности, которые следует учитывать

*   WCAG 2.1 или WCAG 2.2 (основание по всему миру).
    
*   Section 508 (США).
    
*   EN 301 549 (ЕС).
    
*   ISO/IEC 40500 (тот же текст, что WCAG).
    
*   ГОСТ Р 52872 и СНиП — национальные российские стандарты.
    

## 12\. Разница между usability и accessibility

| Параметр | Usability | Accessibility |
| --- | --- | --- |
| Цель | Легкость и удовольствия использования | Доступ к контенту для людей с ограничениями |
| Фокус | Эффективность, понятность интерфейса | Совместимость с вспомогательными технологиями |
| Ключевая аудитория | Все пользователи сайта | Пользователи с различными инвалидностями |
| Метрики | Время выполнения задач, кликабельность | Уровень соответствия WCAG, успешное использование скринридера |

## 13\. Что нужно учитывать при разработке доступного сайта?

*   Семантическая HTML-разметка.
    
*   Логическая структура заголовков и списков.
    
*   Управление фокусом и видимые индикаторы.
    
*   Контрастность текста и фоновых элементов.
    
*   Описание всех нетекстовых элементов (`alt`, `aria-*`).
    
*   Дублированные способы навигации (клавиатура, голос, жесты).
    
*   Корректная валидация форм и понятная обработка ошибок.
    

## 14\. Структура заголовков (H1–H6) и доступность

Заголовки создают иерархию и облегчают навигацию для скринридеров и пользователей.

Правила использования:

*   На странице должен быть один `<h1>` — главная тема.
    
*   Использовать последовательно, без пропуска уровней (не прыгать с `<h1>` сразу на `<h3>`).
    
*   Каждая секция начинается с заголовка следующего уровня.
    
*   Заголовки помогают составлять «таблицу содержания» для скринридеров и сокращают время поиска нужного раздела.
    

## 15\. Правила работы с цветом для доступности

*   Минимальная контрастность текста к фону — 4.5:1 (уровень AA) и 3:1 для крупного текста.
    
*   Избегать использования только цвета для передачи информации (добавлять иконки или текстовые метки).
    
*   Проверять палитру на распространённые типы дальтонизма (deuteranopia, protanopia).
    
*   Использовать инструменты вроде Contrast Checker и симуляторы цветовой слепоты.
    

## 16\. Рекомендации для мультимедиа-контента

*   Видео: синхронные субтитры, расшифровки диалогов.
    
*   Аудио: текстовые транскрипты и описания визуальных элементов (audio description).
    
*   Контролы плеера должны быть доступны с клавиатуры и снабжены ARIA-атрибутами.
    
*   Не автозапускать медиа без явного согласия пользователя.
    

## 17\. Как создать доступный список в HTML с помощью ARIA-ролей?

Простой список:

```html
<ul role="list">
  <li role="listitem">Первый пункт</li>
  <li role="listitem">Второй пункт</li>
  <li role="listitem">Третий пункт</li>
</ul>
```

Для древовидных структур используют:

```html
<div role="tree">
  <div role="treeitem" aria-expanded="true">
    Раздел 1
    <div role="group">
      <div role="treeitem">Подраздел 1.1</div>
    </div>
  </div>
</div>
```

## 18\. Что такое skip-links и как они используются?

Skip-link — скрытая ссылка в начале страницы, которая становится видимой при фокусе.

Она позволяет сразу перейти к основному содержанию, минуя повторяющиеся навигационные блоки:

```html
<a href="#main-content" class="skip-link">Перейти к содержанию</a>
```

## 19\. Разница между `role` и `aria-label`

`role` определяет тип и семантику элемента (кнопка, навигация и т.д.), а `aria-label` задаёт читаемое имя для вспомогательных технологий.

Например, `<div role="button" aria-label="Закрыть">×</div>` сообщит скринридеру, что это кнопка «Закрыть».

Бонус: при разработке стоит следить за новыми версиями WCAG (2.2 и выше), знакомиться с практиками Inclusive Design и привлекать к тестированию реальных пользователей с инвалидностью.
